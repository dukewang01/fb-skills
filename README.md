# fb-skills

酒店餐饮（F&B）合规与运营技能集。可直接放入 agent 的 skills 目录使用。

## 技能清单

### menu-compliance-review — 菜单合规审查
收到菜单、台卡、宴会菜单、BEO 菜单、送餐菜单或餐饮宣传文案时使用。

- **依据**：集团《菜单描述-合规审查清单》12 条 + 《中华人民共和国广告法》《反不正当竞争法》
- **输出**：固定格式的问题清单表（位置 / 原文 / 违反条款 / 级别 / **建议用词**），表后附"须补的标识清单"
- **级别**：🔴 必改 ｜ 🟠 建议改或需确认 ｜ 🟡 提示
- **纪律**：必须给具体替换词；拿不准标"需确认"（误报比漏报更伤信任）；中英都看
- **流程提醒**：改后须由餐饮经理/餐饮总监/行政总厨在集团食品安全系统创建审阅任务，由卫生专员完成审阅

配套参考：
- `references/checklist.md` —— 12 条逐条判定要点与常见原文示例
- `references/banned-words.md` —— 广告法四类禁用语完整词表 + 替换词对照
- `references/special-ingredients.md` —— 特殊食材与药食同源判定口径

### hand-drawn-poster — 手绘感物料
要出「手绘 / 手账 / 纸感」风格的图、海报或 A3 打印物料时使用。

- **手法**：米黄纸感底 + 22px 网格 + `feTurbulence` 噪点；轮廓抖动双描边；便签随机微歪；图钉 / 回形针 / 订书钉 / 胶带点缀
- **关键限制**：没有中文手写体时字仍是黑体，手绘感只能做在线条/框/底纹上
- **随机必须固定种子**，否则每次生成不同
- **管线**：无头 Chromium 渲染 → 自动裁剪 → `fpdf2` 出 A3 PDF，含四个静默坑（截图参数 / 窗口高度 / 裁剪 clamp / orientation）

### delegation-verification — 委派与自证
派子代理做多步交付、或需要证明产物真伪时使用。

- **任务书里引用数据只能从源文件复制** —— 凭记忆转述必错
- **子代理自报 ≠ 证据**，必须自己复量（尺寸 / 关键字 / PDF MediaBox）
- **量法本身会撒谎**：截图不跑定时器（需 `--virtual-time-budget`）；低分辨率读图会编造文字
- **发文件前逐个核路径**；用户说"没收到"先查自己
- **改动要自证"只改了该改的"**：新旧逐像素对比，差异应只落在预期区域

### food-wine-pairing — 餐配酒（通用版）
把菜单与酒水单接起来：先看菜 → 再看菜系 → 最后用本店酒单收口。

- **知识层**（不随店变）：**九条**判断轴（5 看菜 + 3 看服务 + **胶质**）｜**16 类菜系**（v1.1 新增 燕鲍参肚/花胶/炖汤、烧味烧腊、点心蒸点肠粉包点）｜**冲突裁决顺序**（忌配 > 鲜/辣/甜 > 胶质 > 脂肪）｜9 类非葡萄酒酒水 + 无酒精最低配置｜套餐宴席配酒设计 + 台上量算法｜单杯酒单结构 + 价格口径 + 开瓶保质期｜服务话术 + 应答卡
- **配置层**（会变，用时先核）：本店酒单在哪找、成本列对外必剔、多店绝不混用、**本店口径三件套**（杯价是否含服务费 / 单杯杯量 / 可单杯款）
- **机器可读层**：`rules.yaml` —— 判断轴取值口径 + 裁决顺序 + 违例规则（6 条 forbidden / 5 条 advisory）+ 单杯价格口径 + 输入校验 6 坑 + 12 项交付自检
- **输入数据规范**：最低字段集 + 拿到文件先跑 6 项校验（单元格内换行 / 两行一款 / DISPIMG 合并格 / 指针死链 / 跨表重复 / 三源价差）
- **交付前自检清单**：12 项，逐项对应一次真实翻车
- **核心一句**：**单宁只跟脂肪做朋友** —— 遇到鲜、辣、酸、甜，它全是减分项
- **三个最容易推错的**：贵 ≠ 配 ｜ 白葡萄酒不该推给牛排 ｜ 菲力比眼肉更生

## 使用方式

把对应技能目录放进 agent 的 skills 路径即可；技能文件为纯 Markdown，不依赖任何外部服务。

## 说明

本仓库内容为通用模板，不含任何具体门店、品牌、人员或经营数据。

v1.1 的新增口径（裁决顺序 / 胶质轴 / 单杯价格区间 / 开瓶保质期 / 数据校验 6 坑 / 自检 12 项）来自真实菜单与酒单的实测回归；阈值均为经验值，各店可在 `rules.yaml` 的 `store_overrides` 下覆盖。
