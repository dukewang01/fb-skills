# 委派与自证

多步交付给子代理做可以，但**任务书里的每个值、每张图、每条路径都必须能被验证**。下面每条都是真踩过的。

## 一、任务书里引用数据 —— 只能从源文件复制

**凭记忆转述必错。** 同一天在 4 处栽过：部位熟度（眼肉、菲力）、酒款计数（白+起泡 12 款报成 13、红 10 瓶报成 9）。

- 任务书里凡是温度/熟度/价格/数量，**从源文件复制粘贴**，不要凭印象写
- 写完自己回源核一遍；口径不要靠「总数减分项」反推
- 子代理会照你写的做（哪怕错）。如果它**没照做而是按源文件改了**，那是它在帮你 —— 它会标出来，别当它跑偏

## 二、子代理自报 = 自称，不是证据

收到「已完成」后，**必须自己验**：文件在不在、尺寸对不对、内容关键字（改动前值应归零）、PDF 的 `MediaBox`。
- 文件体积/尺寸/`mediabox` 都能用代码量，不要只看它的描述
- 它报告的「已验证」也要复现一次，用**你自己**的方法

## 三、量法本身会撒谎 —— 对不上先怀疑测法

- **无头 Chromium 的 `--screenshot` 在 load 后立刻拍**，页面里的 `setTimeout` 根本没跑 → 必须加 `--virtual-time-budget=N` 才能验需要延迟的交互
- **低分辨率读图会编造文字**：把整页缩小后让视觉模型读，会“读出”源文件里不存在的字符串。判断元素在不在，用**原分辨率分区看**或**精确颜色像素统计**（某色值像素数 > 0）
- 同一份产物两个人量出不同百分比，常见原因是**阈值/背景采样不同**（卡片底色、阴影都会被算作内容）→ 取双方都认的硬指标（如主色像素数）
- 自检结果与预期不符时，**先重跑一遍测法**，再回来怀疑产物

## 四、发文件前逐个确认路径

`MEDIA:` 路径写错 = 静默失败，用户只会说“没收到”。
- 发之前逐个 `if [ -f ]` 测一遍，把结果打印出来
- **用户说“没收到”时，先查自己路径**，不要先去怀疑网络/平台
- 大文件可能被限流：同时备一份小体积版本（图片降采样重打包）

## 五、渲染/输出管线的固定坑（Termux + Chromium）

- `--screenshot=` 与路径**必须同一参数**，空格分开会静默失败
- 窗口高度不够会**静默裁掉内容**，不报错 → 渲染后必须量 `rows[-1] < H-5`
- 裁剪框**必须 clamp 到画布内**（`min(cols[-1]+pad, W)`），否则 PIL 越界补**纯黑边** → 裁完检查四边纯黑像素数 = 0
- `fpdf2` 的 `FPDF(unit='mm', format=(w,h))` **不要传 `orientation`**（传了会变成另一方向）
- 出 PDF 后**读原始字节的 `/MediaBox`** 验尺寸，不要只看代码
- 子代理写文件可能互相撞名 → 让它用独立文件名，别覆盖同跑的兄弟任务产物

## 六、改动要能自证“只改了该改的”

改已知错处的图/文档，重出后做**新旧逐像素或逐字节对比**：差异应该只落在预期区域（例：只改两个值框 → 差异 0.07%、集中在某几行）。差异范围异常就说明改坏了别的地方。
